Lesson 2 of 6

The fallback chain

Three strategies for finding a homepage URL, each ready to fail gracefully into the next.

⏱ ~20 min reading + 15 min exercise 📘 Tutorial 24, Part 3 🗂 agent/research.ts lines 47–108

Why this lesson matters: Job listings are messy. Apply URLs point to job boards, not companies. Company names have legal suffixes. The agent must find a usable homepage despite all of that — and it must never crash when data is missing. The fallback chain pattern solves this. You will use this pattern again whenever input data is unreliable.

The concept: try the best strategy first, fall through on failure

A fallback chain is a sequence of strategies tried in priority order. Each step has a success condition. If the condition is met, it returns immediately. If not — or if the step throws — execution falls through to the next step. The last step is always a guaranteed-or-nothing last resort.

In deriveHomepageUrl(), there are three steps:

Step 1 — Follow redirects Input: external_apply_url ?? source_url Try: fetch(url, { redirect: "follow" }) → parse final URL Pass: hostname is NOT in JOB_BOARD_DOMAINS → return root domain Fail: fetch throws OR hostname IS a job board → fall through Step 2 — Parse original URL directly Input: same url as Step 1 Try: new URL(url) → parse without any network request Pass: hostname is NOT in JOB_BOARD_DOMAINS → return root domain Fail: URL is malformed OR hostname IS a job board → fall through Step 3 — Construct from company name Input: job.company string Try: strip legal suffixes → lowercase → remove non-alphanumeric Pass: cleanName is non-empty → return "https://www.{cleanName}.com" Fail: job.company is null or produces empty string → return ""

Here is the full deriveHomepageUrl() function. Read every line — each try/catch is intentional:

async function deriveHomepageUrl(job: Job): Promise {
  const raw = job.external_apply_url ?? job.source_url;

  if (raw) {
    // Step 1: Follow redirects, parse final URL
    try {
      const response = await fetch(raw, { redirect: "follow" });
      const parsed = new URL(response.url);
      if (!JOB_BOARD_DOMAINS.has(parsed.hostname)) {
        return normalizeToRootDomain(parsed);
      }
    } catch {
      // fall through
    }

    // Step 2: Parse original URL without following redirects
    try {
      const parsed = new URL(raw);
      if (!JOB_BOARD_DOMAINS.has(parsed.hostname)) {
        return normalizeToRootDomain(parsed);
      }
    } catch {
      // fall through
    }
  }

  // Step 3: Construct from company name
  if (job.company) {
    const cleanName = job.company
      .replace(/\s*(Inc\.?|LLC|Ltd\.?|Corp\.?|Co\.?|Limited|Group|Holdings?).*$/i, "")
      .trim()
      .toLowerCase()
      .replace(/[^a-z0-9]/g, "");
    if (cleanName) {
      return `https://www.${cleanName}.com`;
    }
  }

  return "";
}

Notice the empty catch blocks. They are not an oversight. Each catch block is a deliberate "fall through" — the step failed, so try the next one. Logging is intentionally absent here because URL derivation failure is expected (not an error worth recording). Contrast this with conductBrowserResearch(), where failures ARE logged to agent_logs because browser extraction is a core operation.

What normalizeToRootDomain() does

function normalizeToRootDomain(parsed: URL): string {
  const parts = parsed.hostname.split(".");
  if (parts.length > 2 && JOB_SUBDOMAINS.has(parts[0])) {
    return `${parsed.protocol}//${parts.slice(1).join(".")}`;
  }
  return `${parsed.protocol}//${parsed.hostname}`;
}

It strips known job-application subdomains. careers.stripe.com has three parts. parts[0] is "careers", which is in JOB_SUBDOMAINS. So it returns https://stripe.com — the root domain — instead of the careers subdomain. A URL like https://stripe.com/jobs/senior-engineer is returned as-is because parts[0] is "stripe", not a known job subdomain.

Predict what happens if…

Question: Step 3 constructs https://www.stripe.com from the company name. But what if that domain doesn't actually exist — for example, for a small local employer where company = "Pacific Rim Consulting" produces https://www.pacificrimconsulting.com and that site is down or doesn't exist?

Does the code check whether the constructed URL is real? What happens when Stagehand navigates to a domain that doesn't exist? Does the user see an error?

Reveal answer

deriveHomepageUrl() does no validation on Step 3's output. It constructs the URL and returns it. The check only happens in conductBrowserResearch() when Stagehand calls page.goto(homepageUrl) — if the domain doesn't exist, the browser throws a DNS resolution error. That error is caught by the try/catch around the entire browser research block in conductBrowserResearch(), logged to agent_logs, and execution continues with whatever partial content was collected (in this case, nothing). synthesizeDossier() then runs with the fallback message: "No browser research available — synthesize from job posting and candidate profile only." The user gets a dossier generated purely from the job description and their profile. Not ideal, but not an error state.
