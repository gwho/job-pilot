Lesson 0009

Feature 12 — UI Decisions, Navigation Semantics, and Null States

Goal: understand how design tokens are applied in Feature 12 components, why the stretched link is the correct navigation pattern for table rows, the difference between source_url and external_apply_url, and how to reason about every null/empty state decision. Series: Feature 12 Deep Dive (3 of 4).

1 — Design tokens in practice

The rule in context/ui-rules.md:

"Never use Tailwind's built-in color classes (bg-purple-500, text-gray-600) — use project tokens only."

What does this look like in Feature 12? Open components/job-details/JobInfo.tsx. The match badge uses a helper function instead of inline conditional classes:

function matchBadgeClasses(score: number): string {
  if (score >= 70) return "bg-success-lightest text-success-dark";
  if (score >= 50) return "bg-warning-light text-warning";
  return "bg-surface-tertiary text-text-muted";
}

None of these are raw Tailwind colors like bg-green-100. They are all tokens from context/ui-tokens.md. The function returns a complete class string (not a partial) so Tailwind's scanner can detect and include the classes.

Card patterns from the UI registry

The context/ui-registry.md defines two card levels used in Feature 12:

The sub-card uses rounded-xl (smaller radius) nested inside the main rounded-2xl card. The rule: never stack the same border radius — the inner element must be smaller. Open components/job-details/JobInfo.tsx, lines 77–89:

Review question to ask: Does this plan use only token classes (bg-surface, text-text-primary) or does it use raw Tailwind colors (bg-white, text-gray-900)? Raw Tailwind colors in components are a hard rule violation. Flag every one.
Retrieval check: Why does the match badge use a helper function (matchBadgeClasses()) instead of inline conditional JSX like score >= 70 ? "bg-success-lightest" : "bg-warning-light"?
Two reasons. First, readability: a three-tier conditional is easier to read as a named function. Second, and more importantly: Tailwind's scanner needs to see complete class strings in source code to include them in the generated CSS. If you build class names from partial string concatenation (e.g., `bg-${color}-lightest`), the scanner won't detect them and the classes will be absent from the stylesheet. The function returns complete class strings, so the scanner picks them all up on the lines where they appear in the function body.

2 — Navigation semantics: the stretched link pattern

Feature 11 left table rows with cursor-pointer but no navigation. Feature 12 makes them navigable. Open components/find-jobs/JobsTable.tsx, lines 67–84.

Why not onClick with useRouter?

onClick approach (wrong)

<tr onClick={() => router.push(
    `/find-jobs/${job.id}`
  )}>
  • Requires "use client" + useRouter
  • Right-click shows no "Open in new tab"
  • Middle-click does nothing
  • Screen readers can't find it as a link
  • Can't copy the URL

Stretched link (correct)

<tr className="relative ...">
  <td>
    <Link
      href={`/find-jobs/${job.id}`}
      className="... after:absolute
        after:inset-0
        after:content-['']
        after:z-1"
      aria-label="View ... at ..."
    >{job.company}</Link>
  </td>
</tr>
  • Real <a> element with href
  • Right-click → "Open in new tab" ✓
  • Middle-click opens new tab ✓
  • Screen readers announce it as a link ✓
  • No extra JavaScript needed ✓

How the ::after pseudo-element covers the row

The mechanism is pure CSS, no JavaScript:

  1. <tr className="relative"> — gives the row position: relative, making it the "positioned ancestor"
  2. after:absolute — the ::after pseudo-element of the <Link> is positioned absolutely, sizing relative to the nearest positioned ancestor (the <tr>)
  3. after:inset-0 — shorthand for top/right/bottom/left all = 0. The pseudo-element stretches to every edge of the <tr>, covering the full row
  4. after:content-[''] — creates the pseudo-element (without content, nothing renders)
  5. after:z-1 — gives the pseudo-element z-index: 1, ensuring it sits above other cell content (match score bar, text) in the stacking order. Without this, clicks on other cell content might not trigger the link.

The aria-label matters for screen readers. Without it, a screen reader would announce only the visible text: "HSBC." With it: "View Software Engineer at HSBC" — the user knows exactly where the link goes.

Review question to ask: Does the plan use onClick / useRouter for table row navigation? If yes — flag it. Ask whether right-click "Open in new tab" works, and whether screen readers can navigate to it. The stretched link is the correct pattern.
Retrieval check: Why was after:z-1 added during the project review phase rather than during initial implementation?
The initial implementation used after:absolute after:inset-0 after:content-[''] without a z-index. The project review identified that without z-index: 1 on the ::after, positioned elements in other cells (like the match score bar div elements) could render above the pseudo-element, making clicks on those areas miss the link. Adding after:z-1 ensures the pseudo-element is always on top of other cell content. This is a subtle browser stacking behaviour that only appears during manual testing, which is why it was caught in the review's "Minor flag 1" rather than during static analysis.

3 — source_url vs external_apply_url: two different destinations

Open components/job-details/JobInfo.tsx (View Job Post button) and components/job-details/JobActions.tsx (Apply Now button).

FieldExample valueButtonUser intent
source_url hk.jobsdb.com/job/66500000/... View Job Post See the original listing, share it, read the formatted description
external_apply_url hsbc.taleo.net/careersection/hk/... Apply Now Start the application process directly on the employer's system

JobsDB is an aggregator. Employers pay to list jobs there but receive applications through their own Applicant Tracking System (Workday, Taleo, Greenhouse, etc.). The actor scrapes both: the canonical listing URL and the URL the apply button links to.

Open JobActions.tsx:

const applyHref = externalApplyUrl ?? sourceUrl;

The ?? (nullish coalescing) operator handles future Adzuna jobs where external_apply_url may be null. For Adzuna, source_url is both the listing and the apply destination. The fallback ensures Apply Now always has a URL.

Review question to ask: Does the plan distinguish between source_url and external_apply_url? If Apply Now uses source_url, the user lands on the listing and must click Apply again. That's an extra step. The plan should use external_apply_url ?? source_url.
Retrieval check: Both source_url and external_apply_url are string | null in the Job type. If both are null, what does the Apply Now button do?
applyHref = null ?? null = null. The component's if (applyHref) check is false, so it falls through to the <button disabled> branch. The button renders as visually disabled with opacity-50 cursor-not-allowed. The user sees the button but cannot click it. This is the correct behaviour — never navigate to null. For real JobsDB jobs external_apply_url is never null (the actor always finds an apply URL or falls back to source_url itself before saving).

4 — Null and empty states: the three strategies

Feature 12 handles nullable data using three distinct strategies. Choosing the right one depends on what the absence of data means to the user.

Strategy 1 — Hide entirely

The element has no meaningful null state. Its presence implies content.

Strategy 2 — Show "—"

The element's position in a layout must be preserved. "—" means "checked, not available."

Strategy 3 — Show empty state message

Users expect content in a named section. Absence without explanation is confusing.

The decision rule for which strategy to use

Ask: Would the user be confused if this element disappeared?

  • The match badge disappears → no confusion. Badges show when they have content.
  • The salary info card disappears → confusing. The 4-column grid looks broken. Show "—" instead.
  • The "Required Skills vs Your Profile" card is empty → confusing. Users expect skill data. Show an explicit message.
  • The AI reasoning card disappears → no confusion. A card titled "AI Match Reasoning" with nothing in it would confuse users about what the feature means.

whitespace-pre-line and scraped text

Open components/job-details/JobDescription.tsx:

<p className="text-sm text-text-primary leading-relaxed whitespace-pre-line">
  {aboutRole ?? "No description available."}
</p>

The Apify actor scrapes descriptions using innerText. innerText preserves newlines (\n) where HTML block elements were — paragraphs, list items, headings. The default CSS white-space: normal collapses all whitespace including newlines into a single space. A multi-paragraph description becomes one run-on sentence.

whitespace-pre-line preserves \n characters as visible line breaks while still collapsing multiple spaces. The result: paragraph structure without needing to parse HTML.

Review question to ask: If the plan renders a scraped text field without whitespace-pre-line, all paragraph breaks will disappear. Check every field that stores raw scraped text. In Feature 12, that is about_role.
Retrieval check: Why is whitespace-pre-line better than whitespace-pre for scraped text?
whitespace-pre preserves all whitespace — including spaces. Scraped innerText often has inconsistent spacing from indentation or browser-specific rendering. Preserving every space would cause misaligned text. whitespace-pre-line preserves only newlines (the meaningful structure) while still collapsing multiple spaces (normalising the inconsistency). It is the precise tool for innerText output.

Summary

  • All styling uses token classes from ui-tokens.md — never raw Tailwind colors or hex values.
  • Main cards: rounded-2xl p-6. Info stat sub-cards: rounded-xl p-4. Inner radius is always smaller than outer.
  • Stretched link gives table rows native <a> semantics — right-click, middle-click, screen reader support, no extra JS.
  • after:z-1 ensures the pseudo-element wins the stacking order over other cell content.
  • source_url = listing page (View Job Post). external_apply_url = apply destination (Apply Now).
  • Three null strategies: hide entirely, show "—", show empty state message. Choose based on whether absence would confuse the user.
  • whitespace-pre-line preserves newlines in scraped innerText descriptions.
