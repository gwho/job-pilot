Agent Plan Review Checklist

Use this before approving a coding agent plan. Each question turns an opinion into something you can verify.

Review lens Question to ask Evidence to inspect
Scope Does the plan build only this feature, or does it sneak in later features? context/build-plan.md, context/progress-tracker.md
Architecture Does each file do work that belongs in its folder? context/architecture.md, proposed file list
Data ownership Are reads user-scoped and are mutations avoided unless required? DB query clauses, route/page code, feature scope
Contracts Does the plan match real nullable fields and real type names? types/index.ts, existing API responses
User behavior Will the interaction work for keyboard, browser history, and new-tab behavior? Navigation method, links, buttons, accessibility attributes
UI consistency Does the plan reuse tokens and existing visual patterns? context/ui-tokens.md, context/ui-registry.md
Null handling Does every nullable field have an explicit display rule? Job type, plan edge-case table
Verification Would the proposed tests/smoke checks catch the likely regressions? Test commands, manual checks, existing tests
Internal consistency Does any later step contradict an earlier decision? Read plan end-to-end, compare examples to rules
Review formula: opinion = claim + evidence + consequence. If one of those three is missing, ask the coding agent to make it explicit.
